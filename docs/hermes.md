# Hermes integration notes

Research and compatibility checks used the actual upstream [NousResearch Hermes Agent source](https://github.com/NousResearch/hermes-agent), tag `v2026.9.7`, locally resolved and pinned to commit `2237be355906fbe6065ce1815711eee52b2d646e`. The runtime identifies as 0.21.1. The Dockerfile checks the fetched commit and uses the upstream frozen uv lock with Python 3.11. The base Python image is also pinned by digest.

The bridge uses `AIAgent` and the tool registry, with a separate child process and `HERMES_HOME` per invocation/profile. The source resolves profile paths at import time, so changing the home after import would be unsafe. Separate processes also avoid sharing mutable native memory state across camp agents. Parent configuration versions have separate conversation checkpoints. The supervisor keeps a durable invocation journal and a stable invocation ID, refuses concurrent writers and treats an interrupted prior invocation as indeterminate on restart.

The current upstream defaults defer plugin tool schemas behind tool discovery. Managed configuration disables that discovery layer for the small camp tool surface, exposing the seven explicit cube tools directly. Other registry tools are removed and dispatch is guarded; attacker profiles expose only observation and synthetic cyber actions. Private native memory is retained for ordinary analysts. Reusable skill changes go through staged Yamnaya candidates and operator promotion, rather than giving agents filesystem or authority-editing tools.

Model and tool calls use short-lived signed camp/job tokens. The child receives neither provider credentials nor worker/Slack/GitHub keys. A worker-side OpenAI-compatible gateway reserves model requests and caps output. The default transport is Chat Completions; Responses is available for compatible Hermes/provider configurations. Model transport compatibility is distinct from the runtime contract smoke test.

`AIAgent.run_conversation` can return a structured failure instead of throwing. The adapter checks `completed`, `failed`, `partial` and `error` before recording success. It saves the returned conversation atomically only after successful completion and closes the agent. SIGTERM requests a hard cancellation; the supervisor enforces a deadline and ultimately kills a child that does not exit.

The test in `scripts/camps/test-hermes.py` executes the actual pinned Hermes runtime against a local fake streaming model server. It checks tool registration, the observation call, completion, persistent history and rejection of a fabricated delegation call. It makes no paid model request. Run it with `HERMES_SOURCE` pointing to a checkout with its frozen dependencies installed. This test should run whenever the Hermes pin changes; the executor guard is an intentionally version-bound integration point.

Quarto publishing follows the project/source distinction documented in [Quarto's GitHub Pages guide](https://quarto.org/docs/publishing/github-pages.html). Yamnaya deploys the reviewed rendered artifact with GitHub Actions so agent-authored executable documents do not run with deployment credentials. New source revisions are fully rendered; cached/frozen execution is disabled in the scaffold.
